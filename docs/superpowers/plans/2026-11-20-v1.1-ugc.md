# 钓友情报（V1.1 M5）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在钓点详情页交付 V1.1 M5 的「钓友情报」：登录用户发布评论、鱼获、情报，图片与文本过机审，人工抽查与举报兜底，运营审核并采纳情报，用户可以查看和删除自己的内容。

**Architecture:** NestJS API 增加 C 端微信登录、`report` 内容域、内容安全 provider、图片工作桶/发布桶、后台审核接口；Postgres 承担业务数据、限流计数和定时任务锁。小程序增加会话模块、详情页情报区、发布页和最小「我的」页；后台在现有单页工作台加内容审核抽屉。全部功能由 `features.ugc` 开关保护，默认关闭，V1.0 稳定后再实施。

**Tech Stack:** Node 24, pnpm 10, NestJS 11, Prisma 6/PostgreSQL 18, WeChat mini program (native TypeScript), Next.js 16/React 19/Ant Design 6, Jest/Supertest/Playwright, Aliyun OSS.

**Spec:** `docs/superpowers/specs/2026-11-20-v1.1-ugc-community-design.md`

## Global Constraints

- 实现必须等 V1.0 验收稳定后开始；本计划不改变 V1.0 的浏览、地图和 POI 行为。
- 功能开关 `features.ugc` 默认 `false`。关闭时公开列表为空、写接口返回 `FEATURE_DISABLED`、UGC 图片路由返回 404；后台审核接口仍可用。
- 内容类型只有 `comment`、`catch`、`intel`。正文 1 至 500 个 Unicode 字符；图片最多 6 张；鱼获必须有 `fish_key`，重量可选，范围 0.01 至 999.99 kg。
- 审核状态只使用 `machine_pending`、`machine_rejected`、`published`、`human_approved`、`human_rejected`、`removed`。机审拒绝返回 201 + `moderation_status=machine_rejected`，不是 HTTP 422。
- 有图内容整条等所有图片检查通过后才公开；图片检查超时进入人工，不自动放行；人工通过可以覆盖未完成的图片检查，晚到回调置 `canceled`。
- 禁钓点不开放发布，公开情报区隐藏；暂停开放点允许发布；草稿、下线、删除的钓点不可发布。
- 不做全局流、关注、私信、楼中楼、搜索内容、周榜、积分、等级、头像昵称编辑。
- 作者删除后 24 小时内清空正文、图片和鱼获字段；被驳回/下架内容保留给后台审计。
- C 端 access token 2 小时、refresh token 30 天；refresh 每次轮换，重用旧 refresh 时吊销该用户全部会话；`session_key` 不落库、不写日志；C 端和后台 JWT 密钥分开。
- 限流使用 Postgres `rate_limit_counter`，不引入 Redis；API 只信任本机 nginx 的代理头；定时任务用 Postgres advisory lock。
- 公开 UGC 图片先走 `/api/v1/uploads/public/ugc/...`，CDN 就绪后再切换；工作桶保持私有。
- 任何密钥、AppSecret、token、openid、手机号不得进入日志、审计 payload、仓库或测试夹具。
- 小程序界面沿用现有 `#0b2b26`、`#0e6b5e`、`#e8623a`、`#fbfcf8` 配色；可见文案禁止使用 U+2014 和 U+2013 破折号。
- 后台 `report:read`、`report:moderate` 所有角色可用；`user:restrict`、`user:ban` 仅超级管理员和运营。
- 每个任务结束运行对应测试和 `pnpm --filter @szfisher/api openapi:generate`（涉及 API 时），并提交 `openapi/openapi.yaml` 与 `packages/api-client/src/schema.d.ts`。
- 提交信息末尾加 `Co-Authored-By: Claude Code <noreply@anthropic.com>`。

## Review Focus

- **Refresh token 重用或过期**：用户带旧 refresh token 请求时必须拿不到新会话，且该用户全部会话被吊销；`app-auth.e2e-spec.ts` 的 `revokes every session when a rotated refresh token is reused` 覆盖。
- **图片回调缺失或乱序**：有图内容在所有图片 pass 前不得公开；超时进人工；晚到的 risky 回调不得把已下架内容重新公开；`media-moderation.e2e-spec.ts` 的 `keeps image reports hidden until every callback passes` 和 `late callbacks never republish a removed report` 覆盖。
- **不可见钓点或开关关闭**：禁钓、下线、删除的钓点不能通过公开列表或图片路由泄漏内容；开关关闭时 UGC 图片 404；`reports.e2e-spec.ts` 和 `ugc-uploads.e2e-spec.ts` 覆盖。
- **提交非法内容**：条款版本不符、被限制/封禁用户、鱼获缺鱼种、超过 6 张图必须在写库前或公开前被拒绝；`reports.e2e-spec.ts` 的 `rejects missing terms, restricted users and invalid catch fields` 覆盖。
- **并发审核**：两个审核员同时通过/下架，或作者删除与管理员通过同时发生，最终状态一致、发布桶无孤儿、审计有记录；`admin-moderation.e2e-spec.ts` 的 `serializes approve and remove without orphan images` 覆盖。
