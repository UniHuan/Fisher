# 深圳钓鱼助手 V1.0 开发总计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用 9 至 13 周交付深圳钓鱼助手 V1.0，包括可运营的钓点后台、可查询与导航的微信小程序、独立 API 服务，以及上线所需的部署、安全与合规基线。

**Architecture:** pnpm monorepo。NestJS API 与 Worker 共用领域模块，Prisma 访问 PostgreSQL 15；运营后台是 Next.js 静态导出，部署到 OSS + CDN；小程序使用原生 TypeScript 与微信 `<map>`；三个客户端只依赖 `/api/v1`，OpenAPI 3.0.3 是契约唯一来源。

**Tech Stack:** Node 24 LTS、pnpm workspace、TypeScript strict、NestJS、Prisma、PostgreSQL 15、Next.js + React + Ant Design、原生微信小程序、Redis 按需引入、阿里云 OSS/CDN/WAF/SLB/ECS/RDS、GitHub Actions、Jest + Supertest、Playwright、k6。

**Spec:** `docs/PRD_v1.4.md`

## Global Constraints

- Node 24 LTS，pnpm 10 workspace，TypeScript `strict: true`，所有包共用 `tsconfig.base.json`。
- API 基础路径 `/api/v1`，管理端 `/api/v1/admin`；字段 snake_case；统一响应 `{code, message, data, request_id}`。
- 业务码固定：`0` 成功、`40001` 参数错误、`40101` 未登录、`40102` 令牌过期、`40301` 无权限、`40401` 不存在、`40901` 状态冲突、`40902` 幂等冲突、`41301` 过大、`42201` 发布校验失败、`42901` 限流、`50001` 内部错误、`50301` 依赖不可用。
- 主键统一 26 位 ULID；时间 `timestamptz`；坐标 `decimal(9,6)`；金额 `decimal(10,2)`；评分 `decimal(2,1)`。
- 坐标统一 GCJ-02；深圳范围纬度 `22.3` 至 `22.9`，经度 `113.7` 至 `114.7`；超出范围拒绝保存。
- 公开接口只返回 `status=published` 且 `deleted_at IS NULL` 的钓点；草稿、下线、删除一律 404。
- 禁钓点默认不返回；`include_banned=true` 才返回列表与地图；详情可按 ID 访问，但不返回导航坐标与导航按钮。
- 管理端 Cookie 固定为 `__Host-fish_access` 与 `__Host-fish_refresh`，HttpOnly、Secure、SameSite=Lax、Path=/，不设置 Domain；响应体不返回令牌。
- 管理端写操作校验同步器 CSRF Token 与 Origin；CORS 只允许 `https://fish-admin.unihuan.com` 与 `https://fish-admin-staging.unihuan.com`，允许凭据，不使用 `*`。
- 公开分页 `page_size` 最大 50，管理端最大 100；排序字段白名单，禁止客户端传 SQL 片段。
- 图片最多 9 张，单张上传不超过 10 MB，仅 JPG/PNG/WebP；服务端按 EXIF Orientation 旋转、清除 EXIF、重新编码；封面不超过 200 KB，详情图不超过 300 KB。
- 后台是纯静态导出，不使用 SSR、Server Actions 或 Next.js API Routes；小程序不引入 Taro、uni-app。
- V1.0 不引入微服务、GraphQL、Kubernetes；Redis 仅在全局限流、热点缓存或任务锁需要时引入。
- 生产为 2 台 ECS 跨可用区 + 多可用区 RDS + SLB + WAF；目标可用性 99.9%，预算不足时书面降为 99.5%。
- 上线门槛：100 个已发布钓点、必填字段完整率 100%、开放或暂停不少于 90 个、禁钓点不超过 10 个、核心钓点不少于 50 个。
- 性能门槛：首页列表首屏不超过 1.5 秒，详情不超过 2 秒，核心接口 P95 不超过 500 毫秒，50 QPS 基线，200 QPS 压测错误率不升高。
- 安全基线按 OWASP ASVS 4.0 Level 2；依赖无高危漏洞，镜像无严重项，密钥不入库、不入镜像。

## Review Focus

1. **草稿允许为空，发布不允许为空。** 草稿只有 `spot_name` 必填；发布时 `district`、坐标、`address`、`fish_types`、`fee_status`、`water_type`、`venue_type`、`open_status`、`verified_at`、`cover_image_key` 任一缺失返回 `42201` 与字段级错误；已发布钓点编辑时不得清空这些字段。测试放在 Task 4 与 Epic E2。
2. **禁钓点默认隐藏，详情可见但不可导航。** 列表与地图默认排除 `open_status=banned`；`include_banned=true` 才返回；详情按 ID 可访问，返回红色提示、`ban_note`，但 `navigation` 为 `null`，不返回 `nav_latitude`/`nav_longitude`。测试放在 Epic E1。
3. **拒绝定位后主链路仍可用。** 小程序不自动弹系统授权；拒绝后列表不展示距离、按运营权重排序、展示去设置入口，再次进入不重复强弹。测试放在 Epic E7。
4. **刷新令牌复用必须撤销全部管理端会话。** 旧 refresh token 再次出现时返回 401，递增 `token_version`，清除当前 refresh hash，写安全审计；CSRF 缺失或与会话不匹配返回 403。测试放在 Task 5。
5. **导入部分成功必须可解释、可重试。** 100 行中 3 行非法时，97 行创建为草稿，3 行进入错误 CSV；任务记录总数、成功数、失败数；同一文件重复上传返回同一任务，不重复创建钓点。测试放在 Epic E4。

## Delivery Strategy

V1.0 包含三个可独立测试的子系统，不在一个计划里写到每个按钮。按契约先行拆成四份计划，本文件是总计划与第 1 阶段实施方案：

| 计划 | 范围 | 产出 | 编写时点 |
| --- | --- | --- | --- |
| Plan A（本文件） | monorepo、共享契约、数据库、管理端认证、字典、健康检查、CI | 可启动、可迁移、可登录、可生成 OpenAPI 的 API 骨架 | 现在 |
| Plan B | 运营后台页面、表单、导入工作台、POI 管理、审计日志 | 可在 staging 完成钓点录入到发布的静态后台 | M2 契约冻结后 |
| Plan C | 小程序首页、地图、搜索、筛选、详情、周边、定位、导航、埋点 | 可在真机完成查询到导航闭环的小程序 | M2 契约冻结后 |
| Plan D | OSS/CDN/WAF/SLB、Docker、CI/CD、监控、备份、安全与上线演练 | 可发布、可回滚、可监控的 production 环境 | M3 后 |

拆分理由：Plan B 与 Plan C 的文件与接口依赖 Plan A 的 OpenAPI 和共享类型；在 M2 契约冻结前写死页面调用会制造返工。每份计划都必须独立产出可运行、可测试的软件。

**V1.0 非目标：** 微信登录、UGC 上报、收藏、足迹、评分、分享卡片、三地图跳转、iOS App、天气与潮汐、多城市。这些进入 V1.1 或 V2.0，不在本计划排期内。

**实现锁定：**
- 密码 `argon2id`，最少 12 位；5 次失败锁 15 分钟，错误提示不区分账号是否存在。
- 访问令牌为 JWT，30 分钟，claims `sub`、`role`、`token_version`、`jti`；放在 `__Host-fish_access`。
- 刷新令牌格式 `v1.<admin_id>.<32-byte-random>.<hmac>`；数据库只存整串 SHA-256。HMAC 校验通过但 hash 不匹配时视为复用，递增 `token_version`、清除 refresh hash、写安全审计。
- `mfa_token` 为 32 字节随机串，数据库存 SHA-256，放在 `idempotency_key`：`actor_type='admin_mfa'`、`actor_id=admin_id`、`key=hash`、`request_hash=sha256(ip + user_agent)`、`response_json={attempts}`、`expires_at=now+5min`。成功或失败 5 次后删除。
- CSRF Token 为 `base64url(HMAC-SHA256(CSRF_SECRET, admin_id + ":" + access_jti))`，随访问令牌 30 分钟失效；服务端从访问令牌取 `jti` 重算并常量时间比较。
- 管理端会话绝对有效期 8 小时，空闲 30 分钟；`last_active_at` 每分钟最多更新一次。

## Phase 2：第 3 至 6 周核心交付

以下为 Epic 级范围与验收标准。每个 Epic 在开工前转成独立计划（Plan B、Plan C、Plan D），沿用本文件的文件结构、接口与测试风格。

### Epic E1：公开钓点读取 API

**范围：** `GET /spots`、`GET /spots/map`、`GET /spots/{id}`、`GET /spots/{id}/pois`。

**关键规则：**
- 列表只返回已发布；筛选、关键词、分页、排序按 PRD 10.5。
- 距离排序用经纬度边界框加 Haversine；未传坐标按 `sort_weight`、`verified_at`。
- 地图最多 500 点；超过返回网格聚合；禁钓点默认排除。
- 详情禁钓点返回红警与 `ban_note`，`navigation=null`；不返回导航坐标。
- 周边按 `spot_poi.distance_m` 升序，支持类型筛选，展示数据署名。

**验收：** 契约测试覆盖全部查询参数；禁钓、草稿、下线、删除不可见；100 点地图流畅；P95 小于 500 毫秒。

### Epic E2：后台钓点编辑与发布状态机

**范围：** 后台列表、新增、编辑、发布、下线、删除、标记已核实、重复告警、预览。

**关键规则：**
- 草稿只有 `spot_name` 必填；发布校验 PRD 3.10 全部字段，缺失返回 `42201` 与字段级错误。
- 已发布编辑不得清空发布必填字段；下线不删除图片；删除仅允许草稿或已下线。
- `verified_at` 只由「标记已核实」更新；发布要求它已存在，不自动写入。
- 重复钓点告警：同区域、名称相似、坐标距离小于 200 米，返回 `warnings`，不阻断保存。
- 发布、下线、删除、核实写审计日志；发布与下线支持 `Idempotency-Key`。

**验收：** PRD 12.1 对应行全部通过；运营可在 10 分钟内录入并发布一个完整钓点。

### Epic E3：图片上传与 StorageAdapter

**范围：** `POST /admin/uploads`、本地与 OSS 适配器、压缩、EXIF 清除、封面与详情图、发布复制。

**接口：**

```ts
interface StorageAdapter {
  putObject(key: string, body: Buffer, contentType: string): Promise<void>;
  copyObject(sourceKey: string, destKey: string): Promise<void>;
  deleteObject(key: string): Promise<void>;
  getSignedUrl(key: string, expiresSeconds: number): Promise<string>;
  getPublicUrl(key: string): string;
}
```

**关键规则：**
- 单张不超过 10 MB；仅 JPG/PNG/WebP；magic bytes 校验，拒绝 SVG、HTML、PHP、压缩包。
- `sharp` 自动旋转、清除 EXIF、最长边 1600 像素、输出 WebP；封面不超过 200 KB，详情不超过 300 KB，质量从 82 逐级降到 60。
- 工作桶存草稿与待审；发布时复制到发布桶并更新 key；下线不删除发布桶对象。
- 存储 key 使用 `spots/{spot_id}/{ulid}.webp`，不使用原始文件名。

**验收：** 伪装图片、超大文件、EXIF 清除、封面回退、发布复制、签名 URL 用例通过；CDN 公网 URL 可访问。

### Epic E4：Excel 导入与错误报告

**范围：** 模板下载、上传、解析、逐行校验、创建草稿、错误 CSV、任务状态、重复文件幂等。

**关键规则：**
- 单次最多 200 行；列与 PRD 3.11 一致；坐标缺失视为错误行。
- 有效行创建为草稿，无效行进入错误报告；不直接发布。
- 任务记录总数、成功数、失败数、状态、错误文件 key；错误 CSV 含行号、字段、原因。
- 同一管理员重复上传同一文件返回原任务，不重复创建钓点。
- 导入任务由 Worker 处理，PostgreSQL advisory lock 防并发重复消费。

**验收：** 100 行中 3 行非法时 97 行成功、3 行报错；重复上传不产生第二批钓点；任务状态可轮询。

### Epic E5：POI 绑定、同步与距离

**范围：** POI 列表、新增、编辑、绑定、解绑、隐藏、腾讯位置服务适配器、每日同步、同步状态。

**关键规则：**
- 腾讯 POI 以钓点为中心 3 公里，缓存 24 小时，配额 80% 告警。
- `(source, external_poi_id)` 唯一；类型映射按 PRD 3.9。
- `spot_poi.distance_m` 用 Haversine 计算并存储；绑定与解绑写审计。
- 同步任务写 `PoiSyncRun`；后台展示最近同步时间、成功数量、失败原因与配额。
- 腾讯接口失败降级为已有 POI，不阻断详情页。

**验收：** 5,000 个 POI 下周边查询 P95 小于 500 毫秒；隐藏 POI 不返回；同步失败可在后台看到原因。

### Epic E6：运营后台 Web

**范围：** 登录与 TOTP、后台壳、钓点列表、钓点编辑器、地图选点、图片、POI、导入工作台、字典、审计日志。

**关键规则：**
- Next.js `output: "export"`、`trailingSlash: true`，关闭服务端图片优化；不使用 SSR、Server Actions、API Routes。
- 登录页处理 `mfa_required`、`must_bind_totp`、`recovery_codes` 三种状态；CSRF Token 只存内存。
- 钓点编辑器覆盖草稿、发布、下线、核实、重复告警；图片排序与封面；地图选点使用腾讯 JS SDK，Key 限制 `fish-admin.unihuan.com`。
- 所有写操作二次确认；发布、下线、删除、导入必须展示结果与审计提示。
- 前端不隐藏权限作为唯一控制，服务端 403 必须正确展示。

**验收：** Playwright 覆盖登录、TOTP、刷新、钓点创建到发布、导入、下线；1280 像素宽度可用；首屏小于 2 秒。

### Epic E7：微信小程序主链路

**范围：** 首页列表、地图 Tab、搜索、筛选、详情、周边列表与弹层、定位授权、导航、埋点、空/错/弱网状态。

**关键规则：**
- 原生小程序 + TypeScript；`app.json` 声明 `requiredPrivateInfos: ["getLocation"]` 与定位描述。

- 埋点按 PRD 11.1 全部事件，失败不阻塞主流程，本地最多缓存 50 条。

**验收：** PRD 12.1 小程序相关行全部通过；iOS 与 Android 各两台真机；弱网与拒绝定位不阻断主链路。

### Epic E8：部署、可观测性与预发布

**范围：** Docker 镜像、Nginx、OSS/CDN、WAF/SLB、staging、CI/CD、日志、指标、告警、备份。

**关键规则：**

## Spec Deltas Locked by This Plan

以下为实现口径，不改变产品行为；若产品、技术、运营任一方不同意，在开工前按 PRD 第 15 章变更流程记录。

1. `poi_sync_run` 表用于后台同步状态展示，弥补 PRD 8.4 与 10.7 的缺口。
2. `import_job.file_hash` 与唯一约束用于同一文件重复上传幂等。
3. 导入采用“校验后直接创建草稿”，不设单独确认接口；运营在后台逐条补图、核实、发布。
4. 发布要求 `verified_at` 已存在，发布接口不自动写入；首次核实由「标记已核实」完成。
5. V1.0 不创建 `user_session`；V1.1 迁移创建，避免空表与未使用代码。
6. 管理端刷新令牌使用带 `admin_id` 的 HMAC 格式，实现无额外会话表的复用检测。
7. CSRF Token 使用无状态 HMAC，绑定访问令牌 `jti`，不写 Cookie、不落库。
