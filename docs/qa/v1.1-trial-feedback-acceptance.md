## 4. staging 配置要求

部署后按 `docs/ops/deployment.md` 第 14 节执行，核心要求如下。

### 4.1 功能开关

`features.feedback` 种子值为 `false`，生产保持关闭。staging 部署和本地检查通过后打开：

```sql
INSERT INTO config (config_key, config_value, description)
VALUES ('features.feedback', 'true', 'V1.1 体验反馈开关')
ON CONFLICT (config_key) DO UPDATE SET config_value = 'true';
```

打开后确认 `GET /api/v1/config` 返回 `features.feedback=true`。关闭时 C 端写接口返回 `FEATURE_DISABLED`，后台读取不受影响。

### 4.2 权限

`feedback:read` 和 `feedback:handle` 已授予 `super_admin`、`operator`、`reviewer` 三种角色。服务端 `RolesGuard` 是唯一权威；后台入口和按钮只根据 `GET /api/v1/admin/me` 返回的权限名显示。

### 4.3 定时任务与保留

```bash
docker compose --env-file /etc/szfisher/staging.env \
  -f infra/docker/docker-compose.prod.yml exec -T api \
  node apps/api/dist/jobs/purge-feedback.job.js
```

- 删除 24 小时仍为 `pending` 的反馈图片和对象；被反馈引用的对象标记 `used` 后保留。
- 删除创建超过 90 天的反馈，图片标记 `deleted` 后删除对象。
- 使用 `feedback:purge` advisory lock，多实例只执行一次。
- 建议每小时或每日执行一次，并接入连续失败或长时间未执行告警。
- 输出 `event=feedback_purge`，字段 `images_deleted`、`feedback_deleted`、`objects_deleted`；未抢到锁时 `skipped=true`。

### 4.4 私有图片与签名预览

- 反馈截图 key 为 `feedback/{userId}/{ulid}.webp`，只写私有工作桶 `OSS_WORK_BUCKET`。
- 不提供公开反馈图片路由；公开图片路由只服务钓点和公开 UGC。
- 后台详情由 `PreviewSignerService` 生成 15 分钟签名 URL，经 `/api/v1/uploads/preview` 校验后由 API 读取对象。

## 5. 图片来源与授权规则

- 禁止抓取网络图片，禁止使用带水印图片，禁止去水印后使用，禁止使用地图截图、含他人隐私或与钓点不一致的图片。
- 只有 `photo` 类型反馈且用户已在小程序勾选授权提示的图片，才可以进入钓点图片候选。
- 上架前必须人工审核图片内容、钓点一致性和授权范围，不能自动把反馈图片设为封面。
- 每张上线图片记录：`spot_id`、来源（反馈编号或拍摄渠道）、作者、授权方式、许可证、审核人、上线日期。来源登记表由运营维护，至少同时写入反馈备注。
- 没有合格授权图片的钓点继续显示「实景图待补充」品牌占位，不使用假图或未授权图片填充。
