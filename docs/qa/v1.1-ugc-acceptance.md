### 2.1 `test:integration` 阻塞详情

`npx pnpm@10.0.0 test:integration` 先执行 `pnpm db:test:prepare`，其中
`node scripts/prepare-test-database.mjs` 调用 Prisma 的 `migrate reset --force`。Prisma 检测到
Claude Code 后拒绝执行：

```text
Error: Prisma Migrate detected that it was invoked by Claude Code.
```

随后命令退出：

```text
ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL  @szfisher/api@0.0.0 prisma:test:prepare: `node scripts/prepare-test-database.mjs`
Exit status 1
```

该 guard 用于防止 AI 代理对数据库执行破坏性重置。本次未设置
`PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION`，未获得用户对重置数据库的明确同意，也未绕过 guard。

本地 `szfisher_test` 已迁移到当前 schema。作为补充，直接运行 e2e 套件，不执行任何迁移命令：

- 24 个测试文件全部通过，216 个用例通过。
- 包含 Task 13 要求的 `app-auth`、`reports`、`ugc-uploads`、`media-moderation`、`report-actions`、`admin-moderation`。
- 该结果不能替代 `test:integration` 的完整命令。用户在确认本地测试库可重置后，应重新执行
  `npx pnpm@10.0.0 test:integration`。

## 4. staging 配置准备

### 4.1 环境变量

`/etc/szfisher/staging.env` 必须存在以下变量。本文档不记录值。

| 变量 | 要求 | 当前状态 |
| --- | --- | --- |
| `APP_JWT_ACCESS_SECRET` | 至少 32 字符，与后台 `JWT_ACCESS_SECRET` 不同 | 待核验 |
| `WECHAT_MINI_APPID` | `wx0d2443850022120f`（公开值） | 待核验 |
| `WECHAT_MINI_SECRET` | 微信控制台获取，只放 0600 环境文件 | 待核验 |
| `WECHAT_MSG_TOKEN` | 与微信消息推送 Token 一致 | 待核验 |
| `WECHAT_MSG_AES_KEY` | 43 字符 EncodingAESKey，与安全模式一致 | 待核验 |
| `UGC_TERMS_VERSION` | 与已上线法务页面版本一致 | 待核验 |
| `LEGAL_BASE_URL` | `https://fish.unihuan.com/legal` | 待核验 |

核验尝试与阻塞：

- 本机不存在 `/etc/szfisher/staging.env`，该文件只应在 staging 主机。
- 尝试用只读 SSH 核验 staging 主机上的文件存在性和变量名，命令被 Claude Code 环境守卫拒绝。
  本次未尝试其他方式绕过。
- 因此在本文档中，七个变量全部保持“待核验”，而不是“通过”。

用户可在 staging 主机执行以下命令，只输出变量名和 `set` 或 `MISSING_OR_EMPTY`，不输出值：

```bash
for key in APP_JWT_ACCESS_SECRET WECHAT_MINI_APPID WECHAT_MINI_SECRET \
  WECHAT_MSG_TOKEN WECHAT_MSG_AES_KEY UGC_TERMS_VERSION LEGAL_BASE_URL; do
  grep -qE "^(export )?${key}=.+" /etc/szfisher/staging.env \
    && echo "${key} set" || echo "${key} MISSING_OR_EMPTY"
done
```
