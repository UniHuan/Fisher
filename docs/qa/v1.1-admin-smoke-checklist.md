# V1.1 后台审核 10 分钟验收清单

适用范围：staging 后台 `https://fish-admin-staging.unihuan.com`，使用 reviewer 和 operator 账号。  
测试数据已由运维写入 staging，内容都以「【测试】」开头，可以放心通过、驳回、采纳、下架、限制和封禁。

## 准备

- [ ] 用 reviewer 账号登录，确认能进入后台
- [ ] 打开「内容审核」，顶部 Badge 显示待处理数量
- [ ] 确认 tabs 为 待抽查 / 待人工 / 被举报 / 已驳回 / 已下架

## 待人工

- [ ] 找到「【测试】待审评论，请在后台点通过。」
- [ ] 打开详情，确认作者为「钓友 测试甲」，钓点为「深圳湾公园东段钓点」
- [ ] 点「通过」，确认后该条从待人工消失
- [ ] 找到「【测试】待审评论，请在后台点驳回并填写原因。」
- [ ] 点「驳回」，不填原因直接提交，应提示原因必填
- [ ] 填写「测试驳回原因」再提交，成功后出现在已驳回
- [ ] 打开已驳回的详情，能看到驳回原因和审核记录

## 待抽查与采纳

- [ ] 找到「【测试】已发布情报，用于举报、采纳和下架测试。」
- [ ] 打开详情，确认审核记录和举报记录都能加载
- [ ] 点「采纳」，成功后显示已采纳（仅情报类型可采纳）

## 被举报

- [ ] 切到「被举报」，找到原因「虚假信息」的记录
- [ ] 打开详情或处理弹窗，确认能看到被举报内容的图片区域
- [ ] 选择「下架」或「忽略」，确认后状态更新

## 限制与封禁（operator 账号，最后做）

- [ ] 用 operator 账号登录，确认能看到「限制发布」和「封禁用户」
- [ ] 对「钓友 测试甲」执行限制发布，天数 1，原因「测试限制」
- [ ] 确认限制后该用户不能发布，但还能登录浏览
- [ ] 对「钓友 测试甲」执行封禁，原因「测试封禁」
- [ ] 确认该用户的公开内容从列表消失，封禁记录写入审核日志
- [ ] 用 reviewer 账号确认看不到限制和封禁按钮

## 审计与安全

- [ ] 每次通过、驳回、采纳、下架、限制、封禁都能在审核记录里看到操作人、时间和原因
- [ ] 审核记录不包含正文全文、图片 URL、token、openid 或手机号

## 反馈

遇到问题按 `docs/qa/v1.1-trial-feedback-template.md` 记录，附截图、页面、预期和实际。  
封禁后测试数据会被清理；如需重新造数，联系运营重新执行 seed。
