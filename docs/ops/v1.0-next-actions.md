## 7. 安全与变更规则

1. 密钥只通过密码管理器、KMS、临时环境变量或 STS 交付，不进入聊天和仓库。
2. 所有仓库改动走分支、PR、CI；main 不直接 push。
3. 合并前必须通过 `verify`、`integration`、`playwright`、`docker`。
4. admin bypass 只用于单人维护者合并自己发起的 PR，且必须在最新 checks 全绿后使用。
5. 生产变更必须有变更窗口、备份、回滚方案和 go/no-go。
6. 数据库重置、批量删除、历史重写、force push、资源删除必须单独确认。
7. 安全测试只做授权范围内的非破坏性测试，不对生产做压力测试或数据导出。
8. 临时凭据在任务完成后撤销，权限按最小化原则授予。

## 11. 同步方式

每完成一步，按 `docs/private/sync-status.md` 的回执格式同步。建议每次只写：

1. 完成了哪一步，例如 `P0-3 证书` 或 `S-4 staging 部署`
2. 环境：staging / production / 本地
3. 资源 ID、域名、镜像 tag 或 digest
4. 验证命令和脱敏后的结果
5. 阻塞和错误信息
6. 希望 Claude 下一步做什么

不要发送密码、AccessKey、AppSecret、JWT、CSRF、TOTP 密钥、完整 Cookie、真实用户个人信息或未脱敏数据库导出。

Claude 收到回执后会：

- 更新仓库文档或状态表
- 继续执行不需要额外权限的 A 类任务
- 在 staging 或小程序问题中给出下一步命令
- 只在需要新授权时停下
