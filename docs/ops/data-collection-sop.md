# 100 个钓点数据采集与审核 SOP

适用范围：V1.0 上线前 100 个钓点的采集、导入、核实、发布和复核。  
相关文档：[数据质量报告](../qa/data-quality.md)、[后台操作手册](admin-guide.md)、[PRD 1.4](../PRD_v1.4.md)

## 1. 目标

上线门槛：

- 已发布钓点不少于 100 个
- 开放或暂停不少于 90 个
- 禁钓点不超过 10 个
- 核心钓点不少于 50 个
- 必填字段完整率 100%
- 每个核心钓点至少 1 张图
- 每个核心钓点至少 3 个周边场所
- 核心钓点核实不超过 30 天，普通钓点不超过 90 天

数据质量报告：

```bash
DATABASE_URL='postgresql://.../szfisher?schema=public' \
  pnpm --filter @szfisher/api quality:report

DATABASE_URL='postgresql://.../szfisher?schema=public' \
  pnpm --filter @szfisher/api quality:report -- --strict
```

`--strict` 不达标时退出码为 1，用于上线前门禁。

## 2. 数据来源与合规

- 只采集公开可核实的信息，或已获得授权的数据。
- 不抓取地图评论、用户隐私或未经授权的第三方数据库。
- 记录来源类型：官方、运营、用户上报、第三方。
- 图片必须为自有、已授权或明确可用的素材。
- 不把真实用户手机号、身份证、车牌等个人信息写入钓点字段。
- 对来源存疑的钓点先放草稿，不发布。

## 3. 字段规则

| 字段     | 规则                                   |
| -------- | -------------------------------------- |
| 钓点名称 | 使用当地通用名称，避免营销词和重复后缀 |
| 区域     | 使用字典中的深圳行政区                 |
| 坐标     | GCJ-02，深圳范围内，精确到 6 位小数    |
| 导航坐标 | 仅在入口与钓点不一致时填写             |
| 地址     | 可导航的完整地址，不写“附近”等模糊描述 |
| 鱼种     | 使用字典值，多选                       |
| 收费状态 | 免费、收费、未知，按实际情况           |
| 收费单位 | 按天、按小时、按竿、按年、其他         |
| 水域类型 | 海、河、湖、水库、池塘、其他           |
| 场所类型 | 野钓、公园、钓场、码头、礁石、其他     |
| 钓法     | 使用字典值，多选                       |
| 开放状态 | 开放、暂停、禁钓                       |
| 禁钓说明 | 禁钓点必填，写清依据和范围             |
| 停车坐标 | 有明确停车点时填写                     |
| 简介     | 客观描述环境、入口和注意事项           |
| 提示     | 安全、潮汐、收费、夜间等提示           |
| 核实时间 | 实际核实日期，不能用导入时间代替       |
| 来源     | 官方、运营、用户上报、第三方           |
| 排序权重 | 按运营规则，不随意拉高                 |
| 核心钓点 | 只标记重点运营和验证充分的钓点         |

## 4. 坐标与地图

- 统一 GCJ-02。
- 纬度约 22.3 至 22.9，经度约 113.7 至 114.7。
- 坐标落在海里、建筑物内或道路中央的要复核。
- 导航点应落在可到达的入口或停车点。
- 禁钓点可以保留坐标用于审核，但公开详情不返回导航。
- 每个核心钓点至少检查一次地图和街景或实地。

## 5. 图片规范

- 每个核心钓点至少 1 张，建议 3 至 9 张。
- 首图作为封面，优先清晰全景。
- 不使用带水印、二维码、联系方式或他人肖像的图片。
- 不伪造、拼接或过度修图。
- 图片内容与钓点一致，不用其他城市或景点的图片。
- 上传后检查是否被服务端正确旋转和压缩。

## 6. 周边 POI

核心钓点至少 3 个周边场所：

- 停车场
- 公交或地铁
- 厕所
- 便利店
- 钓具店
- 餐饮
- 入口或集合点

要求：

- 名称、类型、坐标、距离完整
- 坐标与钓点距离合理
- 不绑定已关闭或不存在的地点
- 自动同步失败时手工补充
- 隐藏 POI 不在小程序展示

## 7. 采集流程

### 7.1 批量基础数据

1. 按区域分配采集任务。
2. 用 Excel 模板填写基础字段。
3. 运营后台导入，成功行生成草稿。
4. 下载错误 CSV，修正后重试。
5. 去重：同名同区同坐标只保留一个。
6. 统一字典值和来源。

### 7.2 核心钓点补充

1. 选出 50 个核心钓点。
2. 补实拍图、停车点、入口和周边 POI。
3. 填核实时间和核实人。
4. 检查禁钓、收费、开放状态。
5. 运营负责人复核。

### 7.3 发布

1. 发布前逐条检查必填字段。
2. 禁钓点填写禁钓说明。
3. 核心钓点先发布，普通钓点分批发布。
4. 发布后在后台列表和小程序抽查。
5. 发现错误立即下线修正。

## 8. 审核与复核

| 角色       | 检查内容                               |
| ---------- | -------------------------------------- |
| 采集人     | 字段、坐标、图片、来源                 |
| 运营复核   | 名称、区域、收费、开放状态、排序       |
| 内容审核   | 禁钓依据、安全提示、图片合规           |
| 技术复核   | 坐标范围、字典值、图片可访问、POI 绑定 |
| 发布负责人 | 质量报告、抽样结果、发布批次           |

抽样建议：

- 核心钓点 100% 复核
- 普通钓点每个区域至少 20%
- 禁钓点 100% 复核依据
- 新导入批次首日全部抽查前 10 条

## 9. 数据质量报告

关键字段：

- `published`：已发布数量
- `drafts`：草稿数量
- `offline`：下线数量
- `incomplete_required`：必填缺失数量
- `core`：核心钓点数量
- `core_with_images`：有图核心钓点
- `core_with_three_pois`：至少 3 个 POI 的核心钓点
- `published_with_images`：有图已发布钓点
- `published_with_pois`：有 POI 已发布钓点
- `banned`：禁钓点数量
- `open_or_paused`：开放或暂停数量
- `expired_verification`：核实过期数量
- `passed`：是否达到门槛

不达标处理：

1. 先补必填字段和坐标。
2. 再补核心钓点图片和 POI。
3. 再处理过期核实。
4. 最后调整发布批次，不通过降门槛上线。

## 10. 更新与维护

- 核心钓点每 30 天核实一次。
- 普通钓点每 90 天核实一次。
- 收费、开放状态变化在 7 天内更新。
- 禁钓政策变化立即更新。
- 用户反馈或投诉先核实，再修改或下线。
- 每月运行一次质量报告，纳入运营例会。
- 每季度抽查 20% 已发布钓点。
